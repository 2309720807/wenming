# 游戏设计文档 — 文明模拟器

> 本文档是游戏设计的**唯一设计依据**。所有功能实现、平衡调整、内容扩展都必须与本文档保持一致；设计变更必须先更新本文档并经用户确认，再动代码。

---

## 1. 游戏定位

- **名称**：文明模拟器（项目代号 `wenming`）
- **类型**：2D 俯视角射击 + 文明发展模拟（经营/策略/解谜/冒险/动作融合）
- **引擎**：Godot 4.7，2D，Forward Plus 渲染
- **题材**：科幻
- **目标平台**：Windows（后续可扩展）

## 2. 设计核心

玩家同时扮演两个层面：

1. **文明层面（引导者）**：规划文明发展路线，管理资源，解锁科技，建设基地。
2. **英雄层面（战士）**：操控英雄角色进行俯视角射击战斗，探索副本，防守基地。

实时进行、**无强制时间压力**；事件由玩家行为触发，不做强制时间系统。

## 3. 发展路线（5 条，自由组合）

| 路线 | 内容 | 产出 |
|------|------|------|
| 科技 | 研究解锁新装备、武器、建筑 | 装备科技树 |
| 军事 | 扩军、武器升级、征服区域 | 战斗能力 |
| 经济 | 生产链、贸易、资源循环 | 资源产出 |
| 探索 | 地图开放、遗迹解谜、新区域 | 新资源/图纸 |
| 文化 | 声望、事件、文明特色加成 | 全局加成 |

- 路线之间**低耦合**，仅通过资源流相互影响。
- 玩家可自由组合、随时切换侧重，无强制主线。

## 4. 战斗系统

- **视角**：俯视角射击（目标制射击）
- **双场景**：
  - **副本**：开放地图中的遗迹/区域，战斗 + 解谜，产出新资源/图纸
  - **基地防守**：敌人波次进攻基地，检验经营成果（防御工事）
- 敌人强度随文明威胁等级提升（生存压力机制）

## 5. 核心循环

```
经营/发展（文明层） ⇄ 出击战斗（英雄层）
        ↓ 生存压力（威胁等级随文明成长提升）
   生存成功 → 解锁更深区域/路线 → 后期沙盒
```

- **目标**：生存 → 后期开放沙盒（无胜负）

## 6. 技术架构

```
res://
├── scenes/
│   ├── main/       主入口、场景管理器（区域切换）
│   ├── player/     英雄：移动、射击、状态机
│   ├── base/       基地：建造系统、资源存储、防御工事
│   ├── combat/     敌人、弹幕、伤害、波次
│   ├── puzzle/     机关、门、触发事件
│   └── ui/         背包、路线树、对话框、HUD
├── scripts/        模块对应逻辑（外部 .gd，不在场景内嵌）
├── assets/         美术/音频（免费素材包 + 自备）
└── data/           JSON 配置：路线树、物品、敌人、武器、建筑、关卡
```

## 7. 数据驱动约定

- 所有可配置内容（路线、物品、敌人、武器、建筑、波次）放 `data/*.json`
- 平衡调整只改 JSON，不改代码
- 存档分离：文明进度存档 + 英雄状态存档
