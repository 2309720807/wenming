# 游戏设计文档 — 文明模拟器

> 本文档是游戏设计的**唯一设计依据**。所有功能实现、平衡调整、内容扩展都必须与本文档保持一致；设计变更必须先更新本文档并经用户确认，再动代码。

---

## 1. 游戏定位

- **名称**：文明模拟器（项目代号 `wenming`）
- **类型**：2D 实时文明经营策略
- **引擎**：Godot 4.7，2D，Forward Plus 渲染
- **题材**：历史/科幻融合文明发展
- **目标平台**：Windows（后续可扩展）
- **参考游戏**：《文明6》《群星》《纪元1800》

## 2. 设计核心

玩家扮演文明的**引导者**，从远古时代开始，规划文明发展路线，管理资源，解锁科技，建设城市，发展军事与文化，最终实现文明的繁荣。

核心体验：**从零开始建设一个文明的成就感**。

- **实时制**：所有系统资源随时间自然变化，无回合概念
- **被动增长**：人口、资源、科技等按速率持续增长/消耗
- **事件驱动**：随机事件触发，玩家做出决策应对

## 3. 六大核心养成方向

### 3.1 人口与民生 (The Populace)

文明的基石，决定其他所有板块的上限。

- **人口总量与增长**：当前人口/人口上限，增长率（受食物、幸福度影响）
- **人口结构**：不同职业比例（农民、工匠、学者、士兵）
- **幸福度/满意度**：影响人口增长和生产效率（受税收、治安、娱乐设施影响）
- **健康/卫生**：影响死亡率（受水源、医疗设施、污染影响）
- **需求系统**：食物、木材、石料等基础资源的供需平衡

### 3.2 科技与研发 (The Mind)

决定文明的"高度"和解锁新内容。

- **科技树**：分时代（远古→中世纪→工业→现代→未来）的网状结构
- **研究进度**：当前研究项目、剩余回合、科学家分配
- **科技分支**：实用科技（工程、农业）vs 哲学/奥术（文化、魔法）
- **伟人系统**：大科学家、大工程师，提供爆发式增益

### 3.3 经济与资源 (The Vault)

决定文明的运转效率。

- **基础资源**：食物、木材、石料、金属
- **货币系统**：金币（日常维护）、宝石/水晶（稀有战略资源）
- **产出效率**：每个地块/建筑的产出数值
- **贸易网络**：商路数量、贸易收益、贸易范围
- **维护费用**：军队、建筑每回合的维护成本

### 3.4 军事与防御 (The Sword)

决定文明的生存能力。

- **部队编成**：近战、远程、骑兵、攻城等兵种
- **单位经验**：升级带来的晋升选项（"医疗兵"、"游击战"等）
- **城市防御**：城墙血量、防御力、驻军情况
- **战争疲劳**：长期战争导致的资金枯竭或幸福度下降

### 3.5 文化与外交 (The Soul)

决定文明的软实力和外部关系。

- **文化/旅游**：文化值用于扩张国界，旅游值用于"文化胜利"
- **政策/社会制度**："政府卡片"系统（君主制、共和制、独裁制等），提供被动加成
- **外交关系**：AI文明的 attitude（友好/中立/敌对）、贸易协定、同盟、宣战
- **伟人/英雄**：大作家、大艺术家，产出文化点数

### 3.6 地图与探索 (The World)

养成不仅仅在界面里，也在地图上。

- **迷雾系统**：未探索的区域（规划中）
- **地块产出**：鼠标悬停显示食物、产能、金币（规划中）
- **改良设施**：农场、矿场、伐木场等（需工人单位建造，规划中）
- **战略资源**：铁、马、石油等（必须建在资源上才能使用，规划中）
- **网格建设（已实现）**：参考《部落冲突》，在中央网格区域自由建造建筑与装饰，见 3.7

### 3.7 建筑与网格建设系统（已实现）

中央区域为网格化建设地图（参考《部落冲突》建设方式），左侧菜单栏上下滑动选择建筑，选中后消费金币在网格上自由放置。

- **网格规格**：`data/buildings.json` 配置网格尺寸（grid_width/grid_height/cell_size，默认 40px/格，25×14 格 = 1000×560px），居中布置填满中央区域；消息日志（右下角半透明、鼠标穿透）叠加在网格上但不拦截建造点击
- **放置交互**：鼠标悬停显示半透明预览（绿=可建 / 红=不可建），点击确认放置；建筑不可重叠，需在可建区域内
- **建造时间**：放置后进入"建造中"状态（绿色进度条），完成后加成正式生效；施工进度随游戏倍速加速（暂停时冻结，与资源增长节奏一致）
- **取消建造**：点击施工中的建筑即可取消，立即释放格子并**全额返还金币**；菜单栏再次点击已选中的建筑卡片可取消选择
- **成本**：纯一次性金币投入，无维护费
- **障碍清障**：点击障碍任意格（含 2×2 湖泊的延伸格）自动定位锚点并清除，仅扣一次费用
- **升级（已实现）**：点击已完工建筑弹出操作面板，可升级（最高 5 级）或拆除
  - 升级费用 = 基础费用 × 0.75 × 当前等级，升级时间 = 建造时间 × 0.6 × 当前等级
  - 等级加成 = 基础加成 × 等级（Lv.2 住宅人口上限 +20）
  - 拆除返还 =（建造费 + 累计升级费）× 60%，拆除时间 = 建造时间 × 0.6
    - 施工进度条颜色：建造绿 / 升级黄 / 拆除红（拆除中建筑闪烁）
    - 建筑右上角显示等级徽章（Lv.x）
  - **建筑产出总览面板（已实现）**：地图界面底部实时显示所有已建建筑/装饰的累计加成（金币/人口上限/人口增长率/科技/文化/幸福度），监听 `BuildingSystem.bonus_updated` 自动刷新；面板设 `mouse_filter=IGNORE` 不阻挡网格建造点击。实现于 `scripts/ui/map_summary.gd`（独立面板脚本），由 `explore_map.gd` 挂载。

**建筑类型与数值**（配置于 `data/buildings.json`）：

| 建筑 | 金币成本 | 占地 | 建造时间 | 加成效果 |
|------|---------|------|---------|---------|
| 住宅 | 60 | 2×2 | 8s | 人口上限 +10、人口增长率 +0.05/月 |
| 办公楼 | 80 | 2×2 | 10s | 金币产出 +2/月 |
| 学校 | 90 | 2×2 | 12s | 科技 +0.2 点/月 |
| 医院 | 120 | 2×2 | 15s | 幸福度 +2、人口增长率 +0.08/月 |
| 金融中心 | 200 | 3×3 | 20s | 金币产出 +5/月 |

**装饰区**：
- 地图随机生成装饰区（岩石、树木、湖泊），**不可直接建造**，可花费金币清除（岩石 10 / 树木 8 / 湖泊 30），清除后转为可建区域
- 菜单栏提供"装饰"分类，可**手动自建装饰区**（花园 20 金币 1×1 幸福度+1、喷泉 30 金币 2×2 幸福度+2、雕像 40 金币 1×1 文化 +0.1 点/月）

**数值平衡逻辑**：
- 初期金币紧张（初始 100），优先建住宅/办公楼；金融中心 200 金币约 40 游戏月回本（≈3 分钟），形成"积攒→扩张"成长曲线
- 建筑加成动态重算 `gold_rate`/`pop_max`/`pop_growth_rate`/`happiness`/`tech_rate`/`culture_rate`，接入 TimeManager 月度增长循环
- **科技/文化为点数制（非百分比）**：基础速率 0.5/0.4 点/月，随时间累积不封顶，供后续科技解锁/文化扩张消耗

### 3.8 设置系统（已实现）

主界面底栏右下角"设置"按钮（速度控制右侧），打开居中设置面板，包含三项功能：

- **游戏分辨率**：下拉选择 1280×720 / 1600×900 / 1920×1080 / 2560×1440，选择即应用（窗口切换至对应分辨率，UI 按新分辨率矢量重绘，清晰且不错位；窗口自动居中）
- **礼包码**：输入礼包码并兑换，发放金币奖励；大小写不敏感，同一码本次运行内不可重复兑换；礼包码配置于 `data/gift_codes.json`（数据驱动）
- **退出游戏**：点击后弹出确认对话框（内置 ConfirmationDialog），确认后退出游戏
- **开发者调试台**：输入礼包码 `tiaoshitai`（大小写不敏感，GiftCodeManager 特判，不记入兑换记录）开启调试台：
  - 时间控制：倍速 1x/2x/3x/5x/10x、暂停/继续
  - 数值调试：GameState 全部公开数值（资源/速率/人口/幸福度/科技/文化点数）+/- 实时调节
  - 资产浏览：建筑/装饰/障碍物/礼包码实时列出（从数据源读取，新增条目自动出现）
  - 实现：`scripts/ui/debug_console.gd`（框架）+ `debug_stats_panel.gd`（数值）+ `debug_assets_view.gd`（资产），规则见 AGENTS.md 3.2

**模块划分**：
- `data/gift_codes.json` — 礼包码数据配置（数据驱动）
- `scripts/data/gift_code_manager.gd` — 礼包码管理器 Autoload：加载配置、校验、发奖（GameState.add_gold）、防重复兑换、调试码特判
- `scripts/ui/settings_menu.gd` — 设置面板 UI：分辨率下拉、礼包码输入、退出确认，仅调用 WindowManager/GiftCodeManager，不含业务逻辑
- `scenes/ui/settings_menu.tscn` — 设置面板场景（居中弹窗，实例化于主界面）
- `scripts/ui/debug_console.gd` — 开发者调试台框架（挂载于主界面）
- `scripts/ui/debug_stats_panel.gd` — 调试台数值调试面板
- `scripts/ui/debug_assets_view.gd` — 调试台资产数据浏览面板

**UI 动效（界面打磨）**：
- `scripts/ui/ui_anim.gd` — 通用动效工具（UiAnim）：按钮悬停放大/按下微缩、面板入场淡入+放大、数值变化闪烁
- 统一视觉：深蓝玻璃质感（圆角高光边框 + 发光阴影），登录/主界面/探索/设置面板一致
- 主界面顶栏标题紧凑化：左右留白 16px、字号 22，刚好容纳"文明模拟器"五字

### 3.9 本地存档系统（已实现）

开发者调试用本地存档（规则见 AGENTS.md 3.2；正式版如需玩家存档再扩展为多槽位 UI）：

- **存储**：`user://saves/` 目录，JSON 格式，按角色名命名（`<角色名>.json`，同名覆盖更新）
- **内容**：GameState 全部数值（玩家名/时间/资源及速率/人口/幸福度/科技文化点数）+ 建造状态（网格、已放置建筑、加成基础快照）
- **加载**：恢复全部状态并广播数据层信号刷新 UI；网格尺寸异常时自动重新生成（防御旧版本/损坏存档）
- **入口**：
  - 保存：调试台（礼包码 `tiaoshitai`）→"存档管理"分组 → 输入角色名（留空用当前玩家名）→ 保存当前进度
  - 加载/删除：登录首页"已有存档"列表，每行"进入"（加载并直接进入游戏）与"删除"（确认对话框后删除）
- **模块划分**：
  - `scripts/data/save_manager.gd` — 存档管理 Autoload（SaveManager）：序列化/反序列化/列表/删除
  - `scripts/ui/save_list.gd` — 存档列表组件（SaveList）：显示/进入/删除，登录与调试台共用
  - `scripts/ui/debug_save_panel.gd` — 调试台存档管理分组（DebugSavePanel）
  - `GameState.restore_state()` / `BuildingSystem.restore_state()` — 状态恢复接口

## 5. 进阶机制

### 相互制约 (Rock-Paper-Scissors)

- 高税收 = 高金币，但幸福度下降
- 高军事 = 高安全，但经济崩溃
- 高科技 = 高产出，但文化落后容易被同化

### 溢出机制

- 食物溢出 → 自动转化为金币（救济粮）
- 产能溢出 → 自动修复建筑

### 伟人点数

- 每个城市根据建造的建筑类型，产生不同伟人点数

### 动态事件

- 随机事件：瘟疫爆发、黄金时代、蛮族围城等
- 界面预留突发事件弹窗位置

**窗口缩放说明**：
- 设计分辨率 1280×720；**关闭引擎 stretch**，场景根 Control 固定 1280×720 布局，由 WindowManager 按窗口尺寸计算等比系数 `scale = min(宽/1280, 高/720)` 施加到根 Control（登录/主界面 `_ready` 调用 `setup_scale_root(self)` 注册）
- **等比缩放原理**：Control transform 缩放为矢量重绘，切换 1920×1080 等分辨率时字体/图形按新分辨率重新渲染，画面清晰（viewport 拉伸模式放大模糊，已弃用）；布局坐标系恒定 1280×720，任意窗口尺寸不错位
- **历史问题**：曾用 `canvas_items` + 手动 `content_scale_factor` 缩放，但 Godot 4.7.1 存在双重缩放缺陷（factor 设置后逻辑视口被压缩、布局坐标系缩小再放大导致 UI 错位），且引擎 resize 后不自动更新 factor，已弃用
- **输入处理**：引擎 GUI 命中经 Control transform 逆变换自动换算，缩放后按钮/网格点击坐标无需手动转换
- **子窗口（ConfirmationDialog 等）**：不受场景根缩放影响，弹出时按 `WindowManager.current_scale_factor()` 设置 `content_scale_factor` 保持视觉一致
- 信息窗（InfoPanel）与消息日志（MessagePanel）均设 `mouse_filter=IGNORE`（鼠标穿透），不阻挡网格建造操作；操作面板（ActionPanel）保留交互

- 存档分离：文明进度存档 + 英雄状态存档
- **建筑/装饰/障碍物数值**：`data/buildings.json`（建筑成本、占地、建造时间、加成；装饰区；障碍物清除费用）
